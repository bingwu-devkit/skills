# 结果与错误处理

结合 `status`、顶层 `error.category`、`data.failures[].error` 和 `data.submissionStatus` 判断下一步。
`data` 可能为 `null`，先检查再访问。非零退出码不等于没有图片。
CLI 读取提示词或执行离线预览失败时，`data` 可仅包含 `submissionStatus: not_submitted`，
没有 `images` 或摘要字段；不要对这种结果运行摘要校验。

| 状态或情况                                            | 处理方式                                                                             |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `status: success`                                     | 展示已保存图片，说明实际保存数量                                                     |
| `status: partial_success`                             | 展示已有图片并说明失败项；顶层 `error` 可以为空，详情读取 `data.failures`            |
| `status: error`                                       | 先保留并展示已有图片，再说明错误；是否可继续取决于提交状态和已有授权                 |
| `status: unknown` 或 `error.category: result_unknown` | 说明上游可能仍在生成，不自动重提                                                     |
| `status: interrupted`                                 | 保留已有结果；不能保证已取消上游请求；用户主动中断后不自行恢复                       |
| 保存失败                                              | 使用已返回的图片路径；最终记录更新失败时 `recordPath` 可为空，不能靠重新生图恢复保存 |

退出码：0 成功，1 内部错误，2 输入/配置/凭据或本地能力校验错误，3 上游或图片响应错误/结果未知，
4 保存失败，5 部分成功，130 用户中断。

## 提交状态与继续执行

- `not_submitted`：未提交生成请求。可以修正路径、文件编码或参数传递等本地错误，保留用户选定的
  供应商、模型、内容和生成要求，在原授权范围内继续。同一修复无效时停止重复尝试。
- `submitted`：已提交请求；不能据失败结果认定未生成或未计费。
- `result_received`：已收到上游响应；后续解析、下载或保存失败不代表生成未发生。
- `unknown` 或字段缺失：无法据此确认未提交；不自动重提。

同一错误类别可能发生在不同阶段，不仅凭类别推断是否已提交。超时、断网或用户中断后不自动重提。
已提交或提交情况不明时，先说明已有结果、失败原因和下一步；用户已有明确重试授权时遵守其范围与次数，
否则由用户决定是否重新生成。普通“生成图片”请求本身不等于授权失败后重复提交。
未经授权不切换供应商或模型、不降低参数、不拆单或补单。
